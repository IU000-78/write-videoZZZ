~~~markdown
# 白模预演台

## 使用已有工具
- 先读取本轮已有的白模页面、工程与用户提供的场景材料；优先复用同一场景和工程，不重建丢失站位。
- 若已有本工具的可用预览，检查页面成功载入后继续使用。临时 localhost 地址只在本机服务存活时有效；不要把任何历史端口写成永久入口。
- 随技能附带的资源若存在，优先使用 assets/whitebox-studio/whitebox-studio.html。检查文件实际存在再引用。
- 资源尚未随技能保存时，从可核实的工具版本取用单文件 HTML：
  https://github.com/IU000-78/write-videoZZZ/blob/b138fe3580a4174cac0f6e9cb1cb70add91ac726/whitebox-studio/whitebox-studio.html
  通过当前 GitHub/文件能力读取或下载其真实内容，不能把 GitHub 文件查看页当成应用已运行。可下载单文件后打开；file:// 不可用则使用静态 HTTP 服务。首次载入需要访问固定版本 Three.js 的 CDN。
- 用当前受支持的浏览器/电脑能力打开并观察，确认三维场景和实时取景实际出现；服务启动成功或有 URL 不能单独证明预演已可用。
- 缺少写入、浏览器或服务能力时保留已完成内容并明确阻碍；不把“已保存代码”说成“已安装到账号”。
- 当前工具是几何白模编辑器，不支持真实人物模型导入。用户提出“确认后替换真实人物”时，可记录映射和后续需求，不能说当前版本已具备替换能力。

## 建立同一空间
1. 读取本次场景、角色资产、参考视频及用户锁定尺寸；只依据实际可见材料。未知距离标为示意，不宣称实测；不能从单张透视图片假称已自动还原精确建筑。
2. 统一为米；Y 向上，X 正向为东，Z 负向为北。yaw=0° 朝北，90° 朝东。身体朝向、走动方向和摄影机方向分别记录。后续机位或反打不得镜像/旋转整个世界或交换人物。
3. 创建实际需要的人物、墙体、立柱、门框、方块和摄影机。示例大厅的 5 人/7 机位是可删除示例，不套用到新项目；没有要求的角色不加入。
4. 保留每个实体唯一 id 和完整资产映射。可把对象 name 设置为完整注册名；长名称或额外资产关系单独在工程说明中映射，不能靠简称推测。当前工程格式不会保留任意新增自定义字段，资产映射不能只存放在会被导入器丢弃的字段中。
5. 按剧情保留起始站位与朝向。不能为配标签、避遮挡或凑反打自动移动人物。距离检查是脚下的水平直线距离，不等于行走路程、手部接触距离或实际人体碰撞验证。

## 工程格式
使用当前工具可实际导入的 version=1：
- 顶层：version、ratio、selected、activeCamera、objects。
- 每个对象：id、type、name、x、y、z、yaw、pitch、roll、height、width、depth、focal、target、aimHeight；可用 objectDefaults 补全缺省值。
- type 只能为 actor、camera、wall、column、door、box。id 必须唯一。target 为现有 actor 的 id 或 null。
- ratio 为 9:16、16:9、1:1、4:3、2.39:1；优先沿用当前项目画幅，没有依据时说明采用的示意设置，不把工具默认竖屏写成所有剧本的规则。
- actor 的 x/z 是脚下站位，height 为身高，y 不作为人物升降功能。camera 的 x/y/z 为位置。
- target 不为空时朝向持续由目标与 aimHeight 计算；手动 yaw/pitch 在解除锁定后生效；roll 为画面侧倾。
- 允许最多 300 个对象；坐标 x/z 在 -50..50 m，机位高度 y 在 0..30 m，焦距 12..200 mm。不要通过静默夹断来假称用户给定的超限尺寸已精确保留，遇到超限先说明表达限制。
- 焦距采用当前 Three.js filmGauge=36 mm 约定。UI 焦距是几何相机参数，不宣称与所有实体镜头或传感器的视角完全一致。

## 摆位与调整摄影机
- 鼠标拖动和右侧数字坐标都应可用；需要精确距离时输入数值并检查结果。人物和建筑编辑完后再移动摄影机。
- 用俯视平面检查平面坐标、方向和距离，用三维总览检查高度与遮挡；总览观察相机与实际拍摄机位分开控制。
- 在机位列表切换指定摄影机，调整位置、高度、水平角、俯仰、侧倾和焦距；需要持续跟人时选择对准人物与瞄准高度。
- 核对取景中的实际角色、身体局部、前后景和建筑锚点；背景柔焦不能替代画外。相机锁定目标不保证目标一定不被墙柱遮挡。
- 正反打机位与其移动始终位于当前人物连线的同一侧；不能把“对准人物”当成不跳轴验证。
- 工具不支持相机路径或动作播放；所需连续移动用文字和必要静态机位记录，不宣称已经完成动态预演。

## 保存、导出与回写
- 需要保留本次编辑时保存工程 JSON；浏览器自动保存仅代表当前浏览器本地状态，不保证跨设备或账号云端保存。
- 用户调整后的工程是后续空间依据；没有读取新保存的 JSON 或实际界面之前，不从旧示例猜测用户改后的坐标。
- 按本次请求导出站位 PNG 或摄影机取景 PNG。站位图只要人物时隐藏相机/视野，并检查实际导出结果；摄影机取景 PNG 不含相机模型和编辑辅助线。
- 现有 UI 只有北向提示；若交付任务要求八方位完整罗盘，另补齐 N、NE、E、SE、S、SW、W、NW 并核对，而不能声称现有 UI 已自动画全。
- 保留唯一实体、相同距离、朝向、固定场景和机位关系；多人不因竖屏堆成贴脸同框。
- 输出分镜时只在段首集中必要空间锁定；逐镜写可见内容和变化，沿用当前完整资产名称、原台词及段界末态。最终提示词的世界罗盘字母仍按原规则转成明确人物或场景锚点关系。
- 仅在用户明确要求静态图时调用已有导出，不用生成式图片替代精确几何图；静态图通过不等于视频动作、台词、特效或连续性已验证。
~~~
