# 按需站位图与经同意的特效白模

目录：[配图门槛](#一先判断是否需要配图) · [段首约束](#二站位只在对应段落开头约束一次) · [单镜草图](#单一镜头俯视素描草图优先) · [长镜](#一镜到底单张站位草图) · [白模](#白模空间与实际机位构图参考) · [数据与绘图](#三同一套空间数据与图面) · [交付核对](#四按实际交付范围检查)

## 一、先判断是否需要配图

先按剧情和用户意图决定景别，随后检查下表，不为配图增加中景、全景或新镜头。用户本次明确要求的图式与范围优先；纯审核、解释、单句修改及技能维护不自动出图。

| 当前段落 | 默认处理 |
|---|---|
| 全部为近景、胸部以上近景、特写或这些景别的正反打 | 不提供站位图；即使多人真实在场、过肩或局部接触也不自动加图 |
| 确需中景、中全景或全景交代人物关系、走位或交互空间 | 提供一张必要站位图，已有有效图先复用 |
| 有中景/全景，但人物原地独处、空间关系简单且无需图示 | 仍可省图，不按景别机械配图 |
| 有实际特效，且白模能帮助说明空间或作用过程 | 先询问是否需要白模，得到同意后才生成相关图片 |
| 没有实际特效，只有普通走动、对白、火光、虚化或情绪压迫感 | 不主动询问或生成白模；必要站位图仍独立按景别判断 |
| 当前明确只要文字、不要图 | 不生成；保留内部连续性检查，不造图片引用 |

- 人数不再触发配图；三人、五人或画外真实在场人数只影响内部空间核对。单镜、多镜、一镜到底、焦段数值、特效存在和先前穿帮也都不是站位图的独立触发条件。
- 每个适用段落默认一张必要站位图，不自动执行“俯视总图＋关键镜头实际视角线稿＋阶段图＋起落幅”。同一连续移动用一图中的起点、路线和空心终点说明，不按每次换位或每句对白新增图片。
- 同场景的有效图先复用；确有新场景或原图已无法表达的关键变化时，只更新受影响的图与段首说明，不批量重做无关镜号。多镜稿中只有需要空间表达的段落配图，不把每个镜号当成一个需要新图的段落。
- 用户明确索要其他构图图、对照图或白模时按其范围处理，不自动扩成整套参考包；当前明确改变默认门槛时尊重用户要求。

## 二、站位只在对应段落开头约束一次

- 在该段第一个镜号前集中写简短“空间锁定”：实际使用的@参考图、必要人物/机位/场景/道具标记映射、固定锚点、起始位置与身体朝向、关键道具和痕迹状态。已有图仍适用就沿用，不逐镜重新解释。
- 同一段有多镜时，每镜只写焦段、实际机位、可见内容、动作、必要背景及本镜变化；人物走到新位置时写一次动作及明确终点，后镜承接。未移动人物不重抄，镜头换位不让人物或建筑跟着换位。
- C机位须对应实际镜号；需要时在段首一次列明。仅有特写文字稿不为排C编号而新建机位图。图的方向和标记不代替镜头正文的可见动作与必要机位描述。
- 只保留本段有用的映射，不把内部全部坐标、距离、轴线、画外名册和阶段状态导出成百科。特写沿用[简写规则](closeup-prompts.md)，已有草图一句注明用途即可；不强制复述全图图例。
- 段首示例仅示范结构：

```text
空间锁定：方位参考 @大厅站位草图，图仅辅助空间，标记不进入成片。A为@人物甲，B为@人物乙；S1对应@入口门面，固定在S方位。甲面对乙，乙背后留出退步空间，闭合包裹在两人之间。C1对应镜号1。
镜号1：50mm固定双人中景，摄影机在两人连线侧方。@人物甲走到包裹旁停稳，@人物乙仍在原位看向甲。
镜号2：85mm固定@人物乙面部特写，目光朝向画外的甲，听见声响后眉间收紧。
```

此例不规定所有段落的角色、方向、焦段或机位；不要因为例子用了两镜而新增镜头。

### 单一镜头俯视素描草图优先

- 先通过上节景别与空间需要门槛；不是所有单镜都必须画图。需要时只交一张白底黑线黑字的俯视素描，人物用A、B、C……，道具P1、P2……，已有场景资产用S1、S2……，普通固定单镜可用C1标机位。
- 画清必要人物站位、身体朝向、场景锚点及人物/道具起点—途经—终点；每个实体只画一个起始轮廓，终点用空心或虚线落点，不能复制成第二个人或道具。人物/道具路线须与实际动作对应，不能误读为摄影机路线。
- 使用SVG/矢量或Pillow生成实际PNG；旧`render_blocking.py`是数字人物图式，不能直接用其数字PNG冒充A/B/C草图。复用空间数据即可，不为迁就工具改用户图式。
- 草图不替代实际摄影机高度、角度、焦段、焦点和动作次序，不把俯视拍摄、虚线、字母、罗盘或箭头带入成片。已有图可直接沿用；未改空间时不重画。

### 一镜到底单张站位草图

- 同样先过景别与空间需要门槛；纯近景/特写连续长镜省图，不因摄影机移动或多人在场而强配。
- 需要时仅一张A/B/C俯视草图，标八方位、起始站位、必要锚点和人物/道具路径，不画摄影机运动轨迹或途经机位序列，不追加阶段图、实际构图图或起落幅。
- 正文在一个镜号内直接描述摄影机起点、移动/转向、景别与焦点变化及结束构图，不用C1→C2、K1→K2序列。固定、摇摄和升降如实表达，不虚构平移；本次明确另要轨迹图时按指定范围处理。

### 白模空间与实际机位构图参考

- 采用“剧本实际有特效＋白模有空间表达价值＋用户已同意”的门槛。瞬移、变身、能量传播、神力吸附等可作为候选；普通火焰照明、自然运动模糊、打斗、情绪威压或只说“更电影感”不作为特效依据。仅微小局部发光且不需空间辅助时也可省白模。
- 需要时先问“这段特效是否需要白模辅助？”，按[提问流程](question-flow.md#八白模询问与站位配图按需处理)并入现有问题。同一段已明确要求或同意白模即已有授权，不重复问。未答复不是同意，不先生成等待补批；先完成可独立交付的提示词和必要站位图。
- 先前站位穿帮、编号图未稳定表达前后、同场景人数多或已有白模都不触发自动升级。无实际特效不主动提白模；只维护技能不生成当前项目白模。
- 获准后只制作能解释特效起点、作用范围、路径、接触或终点的必要白模图，不默认每镜一张，也不机械叠加编号图、线稿和白模三套。纯近景/特写不因此另配站位图；若该特效局部白模已明确获准，按同意范围制作。
- 空间总图与实际机位构图按任务需要选择，不默认两者全做。总图保留必要墙地、门柱、人物和关键道具；实际构图图从指定摄影机看过去，呈现真实大小层次、前后、朝向、遮挡及作用区域，不能以第二张俯视图冒充。
- 人体用有头、躯干、分开四肢且可辨正反面的粗略模型，不用同形圆柱替代朝向判断；不雕刻五官和服装装饰。白/浅灰无纹理材质及克制体积明暗即可，不加入真人皮肤、装饰和戏剧化假光。
- 同一套场景数据锁定建筑、人物、道具和特效阶段后换相机；反打不重摆人物或复制错误方向背景。多个阶段/视角确经请求且必要时独立命名交付，不默认拼图。静态图只辅助空间、构图和所示姿态；特效的连续速度、触发、受力和声音仍由文字说明，真人外观与火光沿用既定资产。
- 白模同意不等于允许扩写剧情、添加新特效或承诺零穿帮。仅看到成片偏差不能证明一定由编号图造成；用户反馈、图文冲突、实际观察及原因推测分别记录。

## 三、同一套空间数据与图面

- 省图也在内部核对真实在场/画内人物、固定锚点、平面、朝向、起末位置、手别、接触、持物、视线及背景。图文从同一套状态推导，不把画外当离场；POV机位在本人眼位，不为错开符号改变实际位置。
- 世界坐标固定八方位，俯视图标全N、NE、E、SE、S、SW、W、NW，默认N上E右；反打、转身和换机位不旋转或镜像坐标。正文场景朝向/移动写“向N方位”“朝W方向拍摄”；人物相对位置按参照人物自身前后左右，先核身体朝向，不写“某人的SE方向”。位置、面朝与移动方向分开。
- 普通多镜需要图时沿用白底黑色人物序号1、2、3、C机位、S场景和P道具标记，同人同号；单镜/长镜用上述A/B/C草图。图内保留八向罗盘及必要符号，不加人物名、长图例或资产说明；映射只在段首写一次。按图式保留必要路线，不把普通图或工具旧轨迹模式强加到长镜。
- 已有场景资产在对应固定位置标S1、S2……，同一实体两面素材共用一个S位置；不同实体分别编号。完整@资产名、方向及实际参考范围在段首说明。S标记不是把整张素材铺到某一点；门扇开合、损伤、布料取走和痕迹状态按剧情继承，素材不重置变化。
- 已有明确布局优先复用；未确认资产不造@名，未知距离标示意而非实测，不为了放标签虚构墙、门或通道。新图须反推每个实际机位的背景、可达空间和遮挡，符号自洽不能证明三维可拍。
- 数字图可复用[模板](../assets/blocking-template.json)与[脚本](../scripts/render_blocking.py)：`actors`记录包括画外人物的资产、唯一编号、坐标和朝向；`anchors`记录S编号、完整asset、description和role；`cameras`记录与镜号对应的实际位置、朝向、焦段、高度及背景。`paths`保存同一实体的起末路线，不新增角色。
- 工具`diagram_required`只依据已确定景别与空间需要判断默认站位图，不再按人数。`shot_sizes`接受medium/medium_wide/wide或中景/中全景/全景；`needs_spatial_layout`须依据真实调度需要设定。显式请求可覆盖默认门槛，`text_only`禁止图片交付；焦段不能代替景别。
- 旧数字图工具及连续轨迹模式仅供匹配图式或本次明确请求，不能作为当前所有默认图式的输出保证。使用Pillow，字体按运行环境选择，不写死其他任务路径；必要时另补罗盘、P道具和A/B/C，最终必须目视核对。

```bash
python3 <技能目录>/scripts/render_blocking.py <任务>/blocking.json --output <任务>/blocking.png --notes-output <任务>/blocking-notes.txt
python3 <技能目录>/scripts/render_blocking.py <任务>/blocking.json --check-delivery <任务>/blocking.png --prompt <任务>/prompt.txt
```

`--notes-output`或`--describe`只提供待筛选说明，不能逐镜粘贴全部字段；核对后将本段必要信息合并到段首。脚本检查坐标、引用和编号等结构，不能替代语义、遮挡、尺度和可达性审核。

## 四、按实际交付范围检查

1. 先核配图门槛：纯近景/特写无默认站位图；中景/全景有真实空间需要才配；白模有实际特效且用户同意。没有触发就省图，不为完成清单创造图片任务。
2. 有图时核“当前正文→同一空间数据→实际PNG→视觉检查→回复展示或链接”；按当前环境保存规则保存。缺图不谎称已交付，无图正文不残留悬空引用。未绑定平台素材的图名说明为建议引用名。
3. 段首只约束一次必要站位、锚点及映射，后续镜号无冗余图例和整厅名单；动作造成变化有明确终点，画外状态继续继承，固定建筑不随相机移动。
4. 查看实际PNG，检查八向罗盘、实体唯一、编号/字母与资产映射、机位朝向和路线端点；长镜不画摄影机轨迹，单镜/多镜不自动追加构图包。白模仅验收已同意的相关图，不拿旧俯视工具测试代替白模渲染。
5. 修改绘图规则后运行[工具用例](../scripts/test_blocking.py)，按[行为任务](behavior-regression.md)试用相关分支。分别记录技能结构、工具、AI行为和视频验收，不把其中一类通过说成全部有效，也不宣称静态参考保证生成站位。
